# Competitor captures (J1)

The public claim "better than Lovable, Bolt, Framer AI and Base44" (`docs/execution/QUALITY_BAR.md` J1) needs the **same 8 shared briefs** generated by each tool, captured the same way, measured with the same instruments and judged blind against Makeborne. Generating on the competitors is manual (their accounts, their credits). Everything after the published URL is scripted here.

Captures land in `scripts/eval/competitors/captures/<tool>/<briefId>/`, which git ignores.

## Fairness rules

1. **Same text.** Paste the brief exactly as written below: every word, line and punctuation mark. No extra instructions, no attachments, no reference images, no template, theme or style picker, and no "enhance prompt" button.
2. **Fresh project per brief.** One new project for each brief, with no earlier chat in it. If the account has persistent instructions (custom knowledge, a default project prompt, saved brand settings), turn them off before you start, and write down anything you could not turn off.
3. **First complete result.** Accept the tool's first finished result without manual edits. If the tool asks a question or shows a plan before building, answer once with exactly `Please go ahead with your best judgement.` and write that down. Do not press Fix, Retry or Regenerate, and do not send follow-up prompts. If the tool repairs errors on its own without being asked, that repair is part of its first result. If the build fails, the failure is the result: capture what the tool shows, or record the pair as failed.
4. **No cherry-picking.** One run per tool and brief. Never redo a run because the result is weak. The only allowed redo is a run lost to a tool outage (an error page or a timeout, not a bad design): redo it once and record why.
5. **Same conditions.** The default model and settings of your plan. Run all four tools on the same day if you can, and record the date, the plan tier, the model if the tool shows it, the credits used and the tool version or changelog date.
6. **Public and untouched.** Publish to the tool's own public https address. No custom domain, no password protection, no analytics added. Leave the tool's badge alone unless your plan removes it automatically, and write down whether a badge is visible.

## Step by step

For each tool (Lovable, Bolt, Framer AI, Base44) and each of the 8 briefs below:

1. Note the credits or usage counter before you start.
2. Create a new project and paste the brief text from this page (or the `brief` field of `scripts/eval/briefs/<id>.json`; they are the same text).
3. Wait until the tool says it is done. Answer a question or plan with the fixed sentence from rule 3 if one appears.
4. Publish (or deploy), copy the public https URL, and open it in a private browser window. It must load without a login. If it only loads while you are signed in, try the tool's own visibility setting (for example "public app") without changing any content. If that is not possible, record the pair as "not publicly viewable" and skip it.
5. Note the credits used, the plan tier, the model, the elapsed time, the question you answered (if any) and whether a tool badge is visible.
6. Add the URL to `scripts/eval/competitors/urls.json` (copy `urls.example.json` and replace the placeholders). A value can be the URL alone, or an object that also carries your notes, which `capture.mjs` copies into `meta.json`:

   ```json
   {
     "lovable": {
       "w01-restaurant-saffron-table": {
         "url": "https://saffron-table-xyz.lovable.app/",
         "plan": "Pro",
         "model": "default (not shown)",
         "credits": "2.1",
         "toolVersion": "changelog 2026-10-15",
         "generatedAt": "2026-10-20",
         "notes": "answered the plan question once; badge visible"
       }
     }
   }
   ```

When the file is filled in (it can be filled one tool at a time):

```bash
# Check the file against the shared brief ids and the frozen hashes. No network.
node scripts/eval/competitors/capture.mjs --urls scripts/eval/competitors/urls.json --dry-run

# Capture everything, or one tool, or one tool and brief.
node scripts/eval/competitors/capture.mjs --urls scripts/eval/competitors/urls.json
node scripts/eval/competitors/capture.mjs --urls scripts/eval/competitors/urls.json --tool lovable
node scripts/eval/competitors/capture.mjs --urls scripts/eval/competitors/urls.json --tool bolt --brief w05-ecommerce-good-dog
```

Then open `captures/<tool>/<briefId>/shots/1440-first.png` and `meta.json` and check that each capture shows the generated site, not a login wall or an error page. `meta.json` has `status: "suspect"` when the capture saw a password field, a bot challenge, an HTTP error or an almost empty page.

## What capture.mjs does

- **Refuses** any URL that is not `https`, carries a username or password, or points at localhost, a private address, an IP literal or a placeholder host. It sends no logins, no cookies and no credentials. It never clicks, types or submits anything. The only interaction is scrolling.
- **Loads each page once** in Playwright Chromium (1440×900, device scale 1, service workers blocked so every response is recorded) and records a HAR with embedded response bodies (`page.har`). It waits for network idle (up to 30 s), scrolls top → bottom → top so lazy content and scroll reveals fire, waits for idle again and saves the rendered DOM (`dom.html`).
- **Screenshots** the same page load at 1440, 820, 390 and 360 px wide (heights 900, 1180, 844, 780, as in `lib/thresholds.mjs`). It resizes the viewport rather than reloading, scrolls through again at each width, and writes `shots/<w>-first.png` (first viewport) and `shots/<w>-full.png` (full page). The user agent stays desktop Chromium at every width, as in the Makeborne measurements.
- Writes **`meta.json`**: `{tool, briefId, url, finalUrl, capturedAt, title, userAgent, notes[], status, httpStatus, error, briefSha256, generation, browser, capture, signals, files, durationMs}`. `generation` holds your notes from `urls.json`. `signals` records a password field, a bot challenge, visible tool badge text and links back to the tool, so the judge step can mask or flag them.
- **Never captures a page twice by accident.** An existing capture is skipped. `--overwrite` captures again and first moves the old folder to `<briefId>.previous-<stamp>`; nothing is deleted.
- A failed load is recorded (`status: "failed"`, with the error) and is not retried.

## What measure.mjs and judge.mjs do with the captures

- **measure.mjs** treats `captures/<tool>/` as a capture set. It replays `page.har` offline, so the page is measured as it was captured, without loading the tool's servers again. It runs the website instruments that do not need source code: axe at the four widths, CLS, horizontal overflow, text contrast, html-validate on `dom.html`, weight from the HAR, dead links, images, template tells, first screen, and honest content against the brief. W1 and W2 (compile and type-check) do not apply because there is no source. It also computes the set-level diversity metrics (D1–D5) for each tool's 8 sites. Results go to `outputs/eval/measure/<setId>/`.
- **judge.mjs** pairs each competitor site with Makeborne's site for the same brief. The OpenAI judge (a different model family from the Anthropic builder) sees the screenshots at 1440 (first screen and full page) and at 390 with no names, URLs or file names, using the fixed rubric in `scripts/eval/judge-rubric.md`. Every pair is judged twice with the positions swapped, and a pair counts as a win only when both orders agree; otherwise it is a tie. The win rate against each tool gets a 95% interval (brief-level bootstrap, Wilson as a cross-check). The claim needs the lower bound above 50% against each of the four, which with 8 briefs means 7 or 8 wins. `--sheet` builds the blind ten-pair sheet for human designers (J3).
