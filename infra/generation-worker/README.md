# Generation worker foundation

This directory contains a transactional outbox publisher and a separately qualified restricted-role consumer lifecycle. It is not a deployed generation service. No app request handler imports it and no paid provider handler is enabled.

## Publisher contract

`publishGenerationOutbox` requires an initialized pg-boss instance and one dedicated checked-out PostgreSQL client connected to the same database. The caller owns client release and worker shutdown. Queue creation/migration is a separate operator responsibility.

The publisher calls a private definer selector to lock one queued event with `FOR UPDATE SKIP LOCKED`, inserts the pg-boss message through that exact transaction using its `db.executeSql` option, then acknowledges the event. All three actions commit together. It receives only routing IDs and needs no direct application table writes. It skips jobs already terminal, cancelled or carrying a confirmed outcome at selection time; historical skipped events remain unacknowledged. State may change afterward, so consumers must still recheck it. The immutable event UUID identifies the queue message. An existing message must match the complete scope payload before acknowledgment. Delivery is still at least once: consumers must use database leases, fences and dispatch idempotency; a queue message never authorizes a provider call by itself.

## Consumer lifecycle

`queue-runtime.mjs` requires a dedicated low-privilege login explicitly switched into `makeborne_generation_worker` or `makeborne_generation_publisher`. It rejects privileged session logins and extra role memberships, including an operator connection merely configured with SET ROLE. The migration creates NOLOGIN groups, not production passwords. Never use Supabase's service key/operator database URL as a worker credential.

The operator must install/upgrade the pinned pg-boss schema and create the unpartitioned `makeborne-generation-v1` queue first. For that dedicated queue schema, both roles need schema USAGE and SELECT on `version`/`queue`. The publisher needs SELECT/INSERT on `job`/`job_common`; UPDATE/DELETE are denied. The consumer needs SELECT/INSERT/UPDATE/DELETE on those queue tables because pg-boss 12.36.0's failure/retry SQL deletes and reinserts messages. No schema CREATE, queue policy mutation, application table access or broad default grants are required. Partitioned queues and flow/dependency features need separate qualification. Runtime startup has migration, schema creation, supervision, scheduling, instance registration, notifications, reindexing and vacuum monitoring disabled. A separately operated/qualified supervisor is required for expiry/retry; it must not be omitted in production. Local tests use an operator supervisor with a one-second monitor cadence, not the default sixty-second cadence.

`startGenerationWorker` registers one consumer with batch/concurrency one. The database independently binds message ID, event, job and workspace to a published outbox event before leasing. A non-overlapping heartbeat renews the fence. Cancellation, lease loss, a database heartbeat error, bounded operation deadline or shutdown aborts the executor. Unused interrupted work is fenced and receives a durable queued wake-up; dispatched unknown work enters reconciliation and retains every budget hold. Confirmed outcomes survive a crash before queue acknowledgment without redispatch or losing their review stage. Only existing settlement authority may debit/release accounting; the worker has no grant on it.

The caller supplies a trusted executor; no default provider exists. Returning from the executor does not establish success: the database must already contain a confirmed outcome. Scoped approved-input loading and atomic result commit are locally qualified below. The executor still needs to integrate their current authority checks, format-specific validation, provider evidence and isolated build/review. Its operations must honour AbortSignal. The lifecycle returns within a shutdown bound and reports unconfirmed shutdown; the process owner must terminate an uncooperative executor. The caller owns boss/pool closure and OS signal handling. The disposable child harness verifies actual process death/restart, not production deployment or complete provider integration.

## Database authority

Migration `20261008133918_durable_generation_job_leases.sql` extends the existing jobs and reservation authorities. Enqueue and reserve are atomic. Mutations lock workspace, budget, reservation and job in that order. Lease acquisition, renewal, cancellation and dispatch require the private functions. Existing dispatch/release entrypoints cannot bypass a linked job's lifecycle. Never grant the original unfenced function or direct job writes to workers.

An expired worker that has not dispatched can be replaced. A dispatched or uncertain outcome moves to reconciliation and retains its hold; it must not trigger a fresh chargeable attempt or an invented refund. An unused cancellation releases through the original reservation authority once.

## Local verification

It accepts only the explicitly enabled local database. Its dedicated queue schema and committed job fixtures are removed afterward. Evidence: `docs/execution/evidence/M03-T01-R01/`.

`supabase/check-generation-worker.mjs` creates ephemeral local publisher/worker LOGIN credentials in memory, passes the owned child credential through IPC only, and deletes the logins after closing their pools. It tests real restricted-role queue insertion/rollback, consumer heartbeats, cancellation/deadlines/shutdown, killed process recovery, unknown-dispatch holds, normal outcome handoff, and actual death after a synthetic known-zero outcome before queue acknowledgment. No provider is imported/called. Queue schemas/grants are removed and spending policies restored disabled/zero. Immutable zero-cost fixture receipts remain in stopped local workspaces. Evidence: `docs/execution/evidence/M03-T01-R02/`.

## Before production

Local one-dispatch outcome/settlement functions now pass actual SQL and concurrent completion checks; see M03-T02-R01 evidence. Live fenced workers attest through the wrapper; only a database operator may use the ungranted core for independently verified reconciliation. Never infer a zero cost from an unavailable response.

Approved-input authority now passes local qualification (M03-T01-R03). Session identity is retained without a cascading Auth FK so sign-out does not erase the accounting audit. Replay cannot change the session/consents or extend the authorization.

The consumer calls `load_generation_worker_input` under its live fence before invoking the executor, then verifies the original proposal/input hashes and exact source-ID coverage. Returned reference data is deeply frozen. The executor must still validate the format-specific context and original asset bytes. Current session/expiry, creation/editor access, original proposal/source and base revision must remain valid. Actual restricted-login tests serialize source edits/session removal with the scoped read and deny subsequent dispatch. These checks cannot undo a request already sent; confirmed incurred cost must still be recorded and unknown cost must retain its holds.

Still required: service HTTP approval/consent integration; production worker/supervisor credentials, rotation and deployment; live UI progress and actual provider integration; bounded multi-step attempts; full credit grants/adjustments/refunds and customer usage projection; per-unit token/image/media/compute/storage caps; expired/invalid unused-job cleanup, external outcome reconciliation, persistent build receipts, production recovery/load tests and queue retention. An invalid approval currently fails before execution and follows bounded queue retry; the unused reservation still needs terminal/expiry cleanup. Local qualification does not prove these integrations. One reservation currently permits one external draft dispatch. Generation remains closed. The newly authorised first Claude test round is capped at $25, unspent; verify the connected account and enforce/reconcile this round before any paid request.

## Atomic canonical result commit (local M03-T01-R04)

A trusted executor can call the worker-only commit_generation_worker_result function after validating the format-specific candidate. It reuses the original canonical idempotent writer with the dispatch UUID and commits the exact capped outcome/provider usage in the same transaction. Current session/source/access and live fence still apply; exact own-result replay is allowed, later customer edits conflict. No provider details or source payload are returned from this function. It restores request auth context, creates no second revision/ledger, charges no customer credits and never publishes. Actual restricted LOGIN concurrent replay and canonical customer-write contention pass locally.

This function is not wired into an operational executor yet. Website schema/pinned toolchain/asset bytes, isolated build and quality acceptance remain mandatory. A failed save after a request was sent does not erase incurred cost: record independently confirmed failed output cost through existing capped outcome/reconciliation authorities, retaining unknown holds. Saved candidates remain unpublished/unaccepted. See docs/execution/evidence/M03-T01-R04/.

## Website generation and durable compilation (local M03-T01-R06)

`src/lib/generation/website-worker.ts` composes the approved route/proposal, existing Claude adapter, token/price/model/credential/data-boundary bounds, original asset preflight, capped dispatch, exact metering, durable evidence confirmation and atomic canonical save/usage. It returns `build_queued`; it never compiles in a post-save callback. SQL must use an autocommit-only restricted generator pool, never a client inside BEGIN. `reviewQuestions` remain canonical metadata. No public/live provider bootstrap is enabled.

The canonical outcome transaction creates one private `project_builds` operation bound to the job/outcome/version. This table is its durable queue. `build-worker.mjs` polls using a dedicated low-privilege LOGIN switched to `makeborne_project_builder`; the role assertion rejects privileged origins/extra memberships. Builder has six private functions and no direct app/build/ledger reads or writes, queue DML, provider dispatch or credit settlement. It needs no pg-boss schema or generation queue grants. Production credentials and process supervision are separate operator work.

`src/lib/projects/build-worker.ts` loads the actual saved source under an independent live build fence, resolves authenticated original artwork, applies pinned workload preflight, rechecks authority, invokes an isolated byte-verifying runtime, validates its exact receipt and persists immutable compilation evidence. The supervisor renews non-overlapping heartbeats, propagates cancellation/deadline/shutdown and waits for executor cleanup before further polling. Shutdown is bounded; terminate an uncooperative executor process externally. Expired leases can be reclaimed up to three attempts; never recover by repeating paid generation. Terminal receipts are not recompiled. Existing settlement rejects full-source acceptance without compilation and current authority. The obsolete immediate generation result loader is removed.

Production original-asset and private evidence callbacks remain required. Private compiled-output storage, authenticated isolated previews, rendered visual review/repair and cloud compute/storage quotas are unfinished. `compiled` does not mean hosted, preview-ready, customer-accepted or design-qualified. Local qualification uses actual restricted LOGIN, forced child death/recovery, real isolated Docker build/cancellation and mocked zero-cost provider transport. It is not a design benchmark or provider invoice reconciliation. See docs/execution/evidence/M03-T01-R06/.


## Verified submission API (local M03-T01-R07)

## Native presentation composition (local M12-T03-R07)

`src/lib/generation/executor.ts` selects only the exact approved operation from a detached callback registry. Website jobs require their website worker; saved editable composition requires its native worker. An unconfigured handler fails instead of falling back across formats. Every worker independently checks the immutable approval, current authority, tariff, asset bounds and capped dispatch.

Native submission requires both the original administrator-only durable gate and `MAKEBORNE_PRESENTATION_SUBMISSIONS_ENABLED=true`. Both stay disabled by default. A passed native result is a saved editable revision requiring visual review, without a website compilation. `awaiting_review` does not accept, charge, publish or prove visual quality.

`MAKEBORNE_VERIFY_LOCAL_JOBS=true MAKEBORNE_VERIFY_NATIVE_EXECUTION=true` with the ignored local status file runs the existing HTTP qualification through real local Auth/Postgres, restricted-role pg-boss delivery, the native worker and real renderer. Only provider transport is offline. It uses synthetic zero-cost tariffs, private fixture evidence and no artwork, settles without customer debit and restores stopped caps/temporary roles. This helper is not a production bootstrap or artwork resolver. Production supervision, original artwork resolution, studio controls, live design evaluation, richer editable objects and motion remain pending.
