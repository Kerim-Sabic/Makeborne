# Product teardown: Lovable, Bolt.new, v0 (as of 2026-10-18)

Scope: how each product works and why its output/experience is good or bad. Pricing tables are deliberately omitted (already covered on 13 Oct 2026). Sources are mostly official docs/changelogs/engineering posts from 2026, with Trustpilot, Vercel Community and HN threads for complaints. Where a claim comes from a competitor's blog it is flagged.

## 1. Lovable (lovable.dev)

### 1.1 End-to-end flow

**Landing → first prompt.** The homepage/dashboard shows a prompt box labelled "Ask Lovable to create…" with **Build** preselected in a mode picker; you can type before signing up and the prompt is kept through signup. Starting options: **Attach** (mockups/screenshots, `.fig` files since Aug 2026), **Templates** (remix makes an independent copy on any plan), **Build with URL** (a link that carries a prompt), and **Chats** (talk first, then approve a "Create a new project?" card). ([Getting started](https://docs.lovable.dev/introduction/getting-started), [changelog](https://docs.lovable.dev/changelog))

**Design guidance before the first build.** For open-ended visual prompts (landing pages, portfolios, marketing sites) Lovable shows a card with up to four questions: three design directions (colour palette as swatches "from dark and moody to light and clean", heading/body font pairs rendered in their own fonts, layout wireframes such as hero grid / sidebar / bento / gallery) plus sometimes a content question. The first option is preselected, you can type your own preference, "Skip all" uses defaults, and it is skipped for dashboards, admin panels, games, templated projects or projects with a design system. It adds no credit cost. ([Design guidance](https://docs.lovable.dev/features/design-guidance)) Notably, on 8 Oct 2026 the changelog says "the design-direction previews before the first build were removed" — Lovable has been trimming pre-build friction while keeping the questions.

**Generation.** Build mode (renamed from Agent mode) "lets Lovable implement and verify changes directly in your project." Progress appears as visible tasks; a **Details view** has **Timeline** and **Changes** tabs. Crucially, "Lovable does not show an upfront credit estimate before a Build mode request runs." ([Modes](https://docs.lovable.dev/features/modes)) Streaming uses "partials" so thinking and content appear word by word, and the final notification lists "credits used, files changed, build status." ([How Lovable's agents work together](https://lovable.dev/blog/how-lovable-agents-work-together), 24 Sep 2026) Long runs pause at a **check-in** (20 credits by default, configurable 20–100,000 or off) with **Continue**/**Finish up**; running out of credits pauses with **Add credits**/**Finish up**; stopped requests are charged only for work completed. ([Credits and usage](https://docs.lovable.dev/introduction/credits-and-usage)) Build messages can run up to 10 hours and "goal runs" let Lovable work toward one goal for up to 10 hours (Aug 26/30, 2026 changelog).

**Plan mode / Chat mode.** Plan mode (renamed from Chat mode on 5 Feb 2026) writes an editable plan saved to `.lovable/plan.md`; it costs "one credit, plus the cost of any subagent research." Since Aug 3 2026 you can highlight part of a plan and request a change shown as a diff (1 credit per revision); since Sep 9 earlier plan versions are kept. Chat mode (Sep 21, 2026) is discussion only, priced at "a fraction of a credit." Official framing: "Chat mode helps you decide what you want. Plan mode defines how to build it. Build mode changes the app." ([Modes](https://docs.lovable.dev/features/modes))

**Editing.** The **preview toolbar** (10 Jun 2026) replaced the Visual Edits panel with four modes: **Select elements (S)** — click one or Cmd/Ctrl-click several, then describe the change ("Lovable uses the selected elements as context"); **Edit text inline (T)** — type on the page, click Send; **Draw annotation (D)** — freehand/arrows/boxes auto-cleaned and attached as an image; **Add a comment (C)** — pinned threads teammates can reply to. Comments are free; select and draw consume credits; inline text edits get 100 free per account (each recovering 24 h after use) and 2,000 per workspace per day, then cost credits. Follow-ups can be sent while Lovable is working and join at the next stopping point. ([Visual edit](https://docs.lovable.dev/features/visual-edit)) Code editing (Dev Mode) is paid; two-way GitHub sync plus GitLab and Bitbucket; **Drafts** (Sep 9, 2026) let you try changes separately; every change is a restorable version with a bookmarks tab.

**Publish.** **Publish** sits top-right "next to Share" (or ask in chat). Default `[subdomain].lovable.app`; custom domains need a paid plan and can be bought/connected from chat (Sep 1, 2026). The publish dialog runs a ~10-second **Quick scan**; "Findings do not block publishing by default" but admins can block on critical issues. Lovable auto-generates title, meta description, favicon and social image per page, shown in **Social** and **Search** cards; a dedicated **SEO and AI search** tab (May 18, 2026) adds audits, Search Console setup and Semrush research. Visibility: Public or Invite-only on Free/Pro (invite-only added Oct 8, 2026), plus Workspace/Custom on Business/Enterprise. The live site is a snapshot: a dot on Publish signals pending changes until you click **Publish → Publish changes**. Every publicly published app gets a **Trust Center** (Aug 7, 2026). ([Deploy](https://docs.lovable.dev/features/deploy), [changelog](https://docs.lovable.dev/changelog))

**Collaboration/review.** Multiple named preview links with optional passwords and expiry (Business/Enterprise, Sep 4, 2026); guest comments on shared previews (Jun 26); "Visitor analytics" toggle (Jul 14) and a redesigned Analytics view with **Growth tools** that create Google/Meta ads (Oct 14); Slack and Telegram agents; iOS/Android and desktop apps. Workspace features (groups, SSO, audit logs) are enterprise-heavy.

### 1.2 Architecture and generation technique

- **Multi-provider routing.** Lovable processes "more than one billion tokens per minute" at peak across Anthropic, Vertex and Bedrock. Because "prompt caching relies on consecutive requests being sent to the same provider," each project is pinned to one fallback chain for a window; chains are sampled probabilistically from provider weights, which a PID controller adjusts from error rates. ([Routing Billions of Tokens per Minute](https://lovable.dev/blog/routing-billions-of-tokens-per-minute), 4 Mar 2026)
- **Models.** CEO Anton Osika: "we have four different models used in production", some trained in-house; "it is not just one prompt" — prompt components are injected per scenario. Biggest weakness he names: "the model tries out doing a few things and then it kind of gets stuck or just keeps looping"; the "biggest unlock" is re-planning intelligence plus context engineering. ([Strange Loop interview](https://sanalabs.com/strange-loop/anton-osika)) Opus 4.6 (Feb), Opus 4.7 (Apr) and Opus 5 (Jul 30, 2026) were added for building.
- **Agent runtime.** An **Agent Control Plane** spawns/forks/messages agents; context is an append-only "trajectory" event log; compaction runs on a side trajectory so the agent never pauses; if a sandbox dies the run suspends at that boundary "rather than retrying blind." Read-only **subagents** (explore) shipped to all users May 27, 2026. ([agents blog](https://lovable.dev/blog/how-lovable-agents-work-together))
- **Tools and self-checking.** Agent mode's original tool set: codebase search, read files on demand, inspect logs and network, web search, image generation; Lovable claimed a 90% build-error reduction. ([Agent Mode beta](https://lovable.dev/blog/agent-mode-beta), Jun 2025) **Browser testing** (Feb 2026, integrated into building Jun 22) drives the preview in a remote browser — clicks, forms, navigation, screenshots, console and network logs — and can sign in as a Cloud app user; but it is "conservative by default", "runs are slower than normal actions" and it is "not reliable for subtle visual design or color differences." ([Browser testing](https://docs.lovable.dev/features/browser-testing)) Frontend tests (Vitest in the React template) and edge-function checks exist, but "Most of these tools run only when you ask for them."
- **Stack and backend.** React/Vite/Tailwind/shadcn historically; new apps default to **TanStack Start with SSR** since 13 May 2026. **Lovable Cloud** is "built on Supabase's open-source foundation" (database, auth, storage, edge functions, jobs, emails, AI gateway); agent actions on Cloud go through connector permissions (Always/Ask/Never) with destructive actions like dropping a table defaulting to Never. ([Cloud](https://docs.lovable.dev/features/cloud)) Database changes are recorded as Drizzle migrations (Oct 7, 2026).
- **Design systems** (all paid plans since Aug 19, 2026). Components are copied into `src/design-system/<slug>/`, rule files into `.lovable/rules/libraries/`, version pinned in `lovable.toml`. During generation, "adherence checks flag raw colors, one-off values, inline style overrides, and local reimplementations" and Lovable retries before finishing; releases bump a version and connected projects get an "Update available" prompt. ([Design systems](https://docs.lovable.dev/features/design-systems))
- **Cost bounding.** Usage-based Build pricing, check-ins, workspace usage limits/alerts (Oct 7), "Optimize your usage" chat entry point and "ask Lovable about credit usage" (Oct 14 / Jun 18).

### 1.3 Onboarding and activation

Free: 5 build credits/day capped at 30/month (reset 00:00 UTC, no rollover), 20 Cloud credits, 4 AI credits, 1 connector credit per month, plus a daily chat allowance. Daily bonus: 25 messages earns 5 credits; one-time bonuses for adding a domain or inviting a collaborator (Jan 16, 2026). "Free fixes" are limited to 10 per account, renewing 24 h after use (Aug 11). Cost is shown *after* a message under **More options → Credits used**, with a **Free** badge when the daily allowance covered it. ([Credits and usage](https://docs.lovable.dev/introduction/credits-and-usage)) Time-to-aha is a few minutes to a first preview; the design-question card and template remix are the main activation aids.

### 1.4 Quality mechanisms and weaknesses

What looks good: an opinionated preset style — "heavier use of gradients, blurs, and shadows", 12–16 px radius applied consistently, teal/violet palettes, Inter/DM Sans — which also gives it a "medium" customisation ceiling because targeted overrides fight the preset. ([uxskill design-quality comparison](https://uxskill.laithjunaidy.com/blog/v0-bolt-lovable-design-quality.html), Jun 2026) The 2026 security push (Quick scan, Wiz SAST/SCA, Aikido pentesting, Trust Center, automatic revocation of leaked keys) is a response to CVE-2025-48757 (RLS misconfiguration in generated sites, CVSS 9.3, disputed by Lovable).

Known failure modes: fix-one-break-another loops on larger apps; credits charged for the agent's own mistakes; support largely automated. Trustpilot: 4.2/5 from 1,841 reviews, 17% one-star. ([Trustpilot](https://www.trustpilot.com/review/lovable.dev))

Real complaints (2026 unless noted):
1. "Before, you could do SO MUCH with 5 daily credits, now it just runs out before anything has been done." — Connor R, 2★, 17 Oct 2026, Trustpilot.
2. "wasted all credits just in two days without building a single section" — Hamza Khan, 1★, 16 Oct 2026, Trustpilot.
3. "After the first try, the website only displays the header, and the content area is empty." — Dianna Arakelyan, 1★, 15 Oct 2026, Trustpilot.
4. "the credit can't be replenished, and you have to wait 30 days for it to reset." — Arion Kimaris, 2★, 13 Oct 2026, Trustpilot.
5. "It took over 100 steps to complete the product" … reverted changes 10–20 times — windowshopping, [HN](https://news.ycombinator.com/item?id=43640123).
6. "They charge by obfuscated 'credits'." — dworks, [HN](https://news.ycombinator.com/item?id=45999962).
7. "Everyone non-technical I know who vibe coded either ran into a bug they couldn't fix or abandoned their project." — asdev, [HN](https://news.ycombinator.com/item?id=45190425).
8. Positive counterweight: "it was actually a joy to develop software using Lovable. It created my vision in just a few hours" — Erick, 5★, 17 Oct 2026, Trustpilot.

### 1.5 Shipped in the last 6 months and roadmap

Apr 24: Lovable payments (Stripe/Paddle), macOS desktop app, Opus 4.7, chat-history search. May 18: design guidance, mobile apps, MCP server, workspace skills, TanStack Start default, Telegram bot, "Generate files" (PDF/spreadsheet/presentation output in chat, Apr 2). May 27: subagents. Jun 10: preview toolbar. Jun 18: unified credit balance. Jun 22: browser testing integrated. Aug 19: design systems on all paid plans. Aug 26–30: 10-hour builds, goal runs, Slack agent. Sep 4: named preview links with passwords/expiry. Sep 9: Drafts. Sep 21: Chats (cross-project agent that can message projects in parallel). Oct 8: invite-only publishing on Free/Pro. Oct 14: Growth tools, Sign in with Lovable, project restore within 60 days. ([changelog](https://docs.lovable.dev/changelog))

Stated direction: Osika at Dreamforce (Sep 16, 2026) — once software reaches real customers, trust and safety "is the product"; Lovable wants to live inside other interfaces (Salesforce AIforce) and win enterprise security teams ("from 'this last no' to 'the first yes'"). ([TNW](https://thenextweb.com/news/lovable-anton-osika-dreamforce-way-past-vibes-security)) EU inference for enterprise (Oct 1, 2026).

### 1.6 What Lovable explicitly does not do

No client/CRM layer, no agency white-label (the "Lovable badge returns after downgrade", Jul 14), no approval workflow beyond comment threads and preview links, no print/book output, no deck product (it can emit a one-off PPTX/PDF file from chat but not a designed, brand-consistent deliverable), no cross-format brand consistency beyond per-project design systems. Free users cannot buy top-ups, use code mode or add custom domains.

## 2. Bolt.new (StackBlitz)

### 2.1 End-to-end flow

**Landing → first prompt.** A single chatbox; an agent selector (**Standard** / **Max**; **Forge** when enabled) at the bottom of the box; optional **Enhance prompt** which since May 2026 "asks guided questions"; **Plan mode** to "build a plan and review it before code generation"; a design-system picker on Teams; the **Bolt Templates marketplace** (Aug 2026) with **Preview** then **Use template** ("Starting is free, but customizing spends tokens"); Figma and Google Stitch import; "Migrate from GitHub or Lovable"; include "mobile app" in the first prompt for an Expo project. ([Start a project](https://support.bolt.new/building/start-project), [FAQ](https://support.bolt.new/concepts/faq))

**Generation.** Bolt "creates a new project and begins building": files are created visibly in real time, dependencies install, a dev server boots and the preview appears — all inside the browser tab, because "Bolt runs on WebContainers, which runs a full development environment directly in your browser." When the preview errors, an **Attempt fix** button appears; the docs warn "Each automatic 'Attempt fix' click uses tokens." In Plan mode, "Bolt will generate a plan and show you an Implement plan button." ([Token efficiency](https://support.bolt.new/best-practices/maximizing-token-efficiency), [Preview issues](https://support.bolt.new/troubleshooting/preview-issues)) Prompts can be queued (up to 20, reorderable, pausable) while Bolt works (Aug 2026); voice dictation (Aug 2026).

**Editing.** Toggle `<>` to **Code view** (open/create/edit/delete files; auto-rebuild on save; a **Terminal** at the bottom where `npm run build` surfaces compile errors). "Direct edits in Code view and restoring a version from version history don't use tokens." A version is saved after every processed prompt; **Version History** moved to the top nav (Jul 2026). **Visual edits** via the **Select** tool (Sep 2026) with "Pick from layers": edits are "batched and only consume tokens when saved." `@` tags files/folders in prompts (Apr 2026). **Preview comments** pinned to a spot on the page can be "sent to Bolt as prompts" (Oct 2026). Note: Bolt does not advertise a dedicated diff view in its docs; the old "Discussion mode" was retired on Aug 3, 2026 and replaced by Plan mode. ([Release notes](https://support.bolt.new/release-notes))

**Publish.** **Publish** top-right → about a minute → a random `*.bolt.host` name you can rename via the pencil icon. Free hosting: "up to 10 GB of bandwidth and 333,333 web requests per month", sites go offline for the rest of the month if exceeded, and show a "Made in Bolt" badge. Visibility **Public** or **Private** (paid; invite viewers by email or trusted domain). Custom domains are paid, and "Sites with a custom domain can only be published publicly." **Run security audit** (paid, no tokens) auto-fixes findings before publish. Changes are not live until you click **Update**. Publishing via the button is free; "Prompting Bolt to publish your project decreases your token balance." Netlify remains an alternative target. ([Publish](https://support.bolt.new/cloud/hosting/publish), [FAQ](https://support.bolt.new/concepts/faq))

**Collaboration.** Real-time multiplayer with **Viewer / Editor / Co-owner** roles and a projects dashboard (Apr 2026); "Collaborators who edit the project use tokens from their own account." Publishing was separated from sharing (Apr 2026). Teams get shared design systems, team templates, org-level GitHub app and a shared prompt queue.

### 2.2 Architecture and generation technique

- **Runtime.** WebContainers run Node.js (compiled to WASM) inside the tab — zero-install, but the preview is not the production runtime. **Bolt Cloud** (Sep 2025) provides the hosted side on Supabase: Postgres, auth, storage, edge functions, realtime ([Supabase blog](https://supabase.com/blog/bolt-cloud-launch)); Supabase connections are "available with Vite projects. Next.js projects are not supported." ([Supabase integration](https://support.bolt.new/integrations/supabase))
- **Models and agents.** Sonnet 4.6 became default and Opus 4.7 available (Apr 2026); in May 2026 Bolt "replaced individual model choices with two agents, Standard and Max" — Standard "fast and token-efficient", Max "thinks more about each step"; the model is chosen automatically. **Bolt Forge** (research preview Sep 14–Oct 14, 2026) runs open-source models (GLM 5.3, Kimi K3, DeepSeek v4 Pro) with more included usage, via a $9 Bolt Lite plan. ([Agents](https://support.bolt.new/building/using-bolt/agents), [release notes](https://support.bolt.new/release-notes))
- **Context model = the cost model.** Bolt's own FAQ: "most token usage is related to syncing your project's file system to the AI." The efficiency guide therefore tells users to keep projects small, split large files, clear context, prefer Plan mode, use buttons instead of prompts, and avoid repeated Attempt fix. There is no published planning/self-check loop beyond this; the security audit is a separate on-demand pass.
- **Design systems.** Teams upload npm packages, Storybook, GitHub repos or CSS; "Bolt reads your design sources and builds a Storybook inside Bolt from them"; systems can be attached/detached per project and set as a workspace default. ([Add design system](https://support.bolt.new/building/design-system/add-design-system))
- **Skills** (Jul 2026): reusable instructions applied automatically when relevant.
- **Bolt Slides** (Jul 2026, MIT): a Vite + React deck framework where each slide is a live component; a bundled `.bolt/skills/slides/SKILL.md` "teaches the agent how to theme, compose, and write the deck"; Sep 2026 added visual text/colour editing, slide reorder, speaker notes, presenter view and PDF/JSON export. ([GitHub](https://github.com/stackblitz/bolt-slides), [release notes](https://support.bolt.new/release-notes))
- **Data.** Model training on user projects is on by default except EU/UK/Swiss accounts (Sep 2026). No public API, CLI or SDK.

### 2.3 Onboarding and activation

Free plan: Standard agent only, public sites only, badge, no custom domain; third-party trackers report ~1M tokens/month with a 300K daily cap. Templates are free to open. Tokens are explained only in docs and a usage meter; the "Enhance prompt" guided questions and Plan mode are the pre-spend guards. Time-to-first-preview is the fastest of the three (no VM boot). ([Preuve review](https://preuve.ai/blog/bolt-new-review) — competitor-authored, token figures secondary)

### 2.4 Quality mechanisms and weaknesses

Design: "indigo-to-violet gradient", Inter/system-ui, Lucide or Hero icons, "occasionally emoji on complex prompts"; the uxskill comparison calls Bolt the "lowest-common-denominator" version of a professional web app, i.e. the most generic of the three. ([uxskill](https://uxskill.laithjunaidy.com/blog/v0-bolt-lovable-design-quality.html))

Failure modes: whole-file rewrites on small fixes ("when you ask Bolt to fix a simple bug or syntax issue, it often rewrites the entire file, breaks your UI/UX structure" — Product Hunt reviewer via [Superdesign](https://superdesign.dev/blog/bolt-review)); migration error loops; 2,000–3,000-line files; and the preview/production gap — env vars that live only in Bolt, loose dependency versions, auth redirects pointing at the preview URL, security rules that "can ship switched off"; asking the AI to fix deploy errors wastes tokens because it "can read the project files but not the host's logs, environment settings, or DNS." ([Rocking Tech](https://rockingtech.co.uk/blog/bolt-new-works-in-preview-breaks-in-production), Jun 2026) Trustpilot 1.6/5 from 204 reviews, 83% one-star (G2 ~4.3); StackBlitz has not replied to reviews. ([Trustpilot](https://www.trustpilot.com/review/bolt.new))

Real complaints (2026):
1. "the user tokens are gobbled up faster than a starving pirranha." — Tezla, 2★, 28 May 2026.
2. "it just kept draining the tokens as it tried to fix what should have been coded right in the first place." — Steve Parker, 2★, 20 Jul 2026.
3. "It consistently has server errors, it consistently builds what it wants to steal your tokens." — Ebonie, 1★, 24 Jul 2026.
4. "One can't commit to GitHub, it a eternal loop of asking to connect." — Vita, 1★, 26 Aug 2026.
5. "the exported files were completely different and did not work." — calM dowN, 1★, 24 Jul 2026.
6. "No refunds, no help." — Tan Silliksaar, 2★, 25 Sep 2026.
7. "nothing short of a full blown waste" (10–15M tokens on basic fixes); top reply: use Bolt "to frame up about 60-70% of where you want to be" — [r/boltnewbuilders](https://www.reddit.com/r/boltnewbuilders/comments/1icq1t3/) via Preuve.
8. Positive: "Bolt was my first exposure to vibe coding and what it does is amazing." — Will Bradwell, 5★, 28 Aug 2026.

### 2.5 Shipped in the last 6 months and roadmap

Apr: Sonnet 4.6 default, @-file tags, Pick from layers, multiplayer + roles, publishing split from sharing, org GitHub app. May: Standard/Max agents, Stitch import, guided Enhance prompt. Jun–Jul: leaked-password protection, Bolt Slides, skills, security audit in Publish menu, Safari support. Aug: template marketplace, Plan mode replaces Discussion mode, v1 Agent retired, voice, 20-prompt queue. Sep: visual edits via Select, Slides editing/export, Bolt Forge, model-training toggle. Oct: preview comments → prompts, preview theme switcher. ([Release notes](https://support.bolt.new/release-notes))

Direction: CEO Eric Simons says 2026 growth is majority B2B ("the 'Anthropic' approach") and that everyone will have "their own agentic team"; a Microsoft Azure/M365 partnership positions Bolt for enterprise design-system-governed building. ([Sacra](https://sacra.com/research/eric-simons-bolt-b2b-vibe-coding/), [Bolt blog](https://bolt.new/blog/bolt-microsoft-partnership))

### 2.6 What Bolt explicitly does not do

No CRM/client layer, no white-label on Free (badge), private sites and custom domains paid-only, custom-domain sites cannot be private, no approval/review state, no print or book output, no public API/CLI, Supabase only on Vite projects. Slides exist but are a code framework for builders, not a client deliverable pipeline.

## 3. v0 (Vercel, v0.app)

### 3.1 End-to-end flow

**Landing → first prompt.** v0.app shows one prompt box with a model picker (**Mini / Pro / Max / Max Fast**, four tiers since Jun 8, 2026, with per-model rates on hover and an "Add models" browser since Sep 22), template chips (Contact Form, Image Editor, Mini Game, Finance Calculator), a community template gallery, attachment support (images, ZIPs, Excel/Word, Figma files/URLs), a design-system picker, skill chips and slash commands (Jul 21), and a **Tools** dropdown whose **Permissions** row sets terminal autonomy to **Ask / Auto / Full** (default Auto; "System deny rules still apply in Full mode"). ([Superdesign v0 review](https://superdesign.dev/blog/v0-review) for landing layout; [Terminal commands](https://v0.app/docs/terminal-commands); [changelog](https://v0.app/changelog))

**Generation.** Since Agent mode (Aug 11, 2025) v0 "Makes a step-by-step plan to work on your request", "Searches the web, handles failures, and returns results with citations", "Reads files", "Inspects live sites, takes screenshots, and summarizes findings" and "Spots errors, compares implementations". ([v0.dev → v0.app](https://vercel.com/blog/v0-app)) Vercel staff described the launch as adding "task list creation", "queued messages", "looking up docs for libraries you mention" and "automatic model selection means v0 can use a different model for reasoning" — which is why the model selector was removed, then re-added as tiers in 2026. ([Agent mode feedback thread](https://community.vercel.com/t/agent-mode-feedback-thread/18428)) The docs promise a "Real-time preview of your app, with visual progress indicators and rich UI feedback for all agent actions." ([What is v0](https://v0.app/docs)) 2026 additions: terminal commands behind a permission prompt (May 12), browser screenshots from preview testing shown in chat (May 15), in-form clarifying questions (Jun 19), grouped tool approvals (Jul 7).

**Preview.** Since Feb 4, 2026 the preview is "a lightweight virtual machine that runs your app in an isolated environment" replacing the browser-based preview; "Previews now run your full application exactly as it would in production." Sandboxes run up to 24 h (Jul 7); paid chats that exhaust CPU/RAM "move up a VM size tier and restart in the background" (Aug 28). ([FAQ](https://v0.app/docs/faqs), [changelog](https://v0.app/changelog))

**Editing.** Two preview tabs: **Code** (a VS Code-style editor since Feb; a lightweight Code tab Sep 25 where you "browse, edit, and comment on project files"; selecting gutter lines adds them as context for the next prompt) and **Design**. **Design Mode** turns the cursor into a selector; the panel edits typography (family, size, weight, line-height, letter-spacing, alignment, decoration), text and background colour, margin/padding per side, border, opacity, radius, shadow and text content; undo/redo/reset and a before/after toggle; **Apply** "serializes your edits, instructions, and screenshots, sends them to the chat, and generates an updated project version", so every Apply is a normal version with a diff you can revert. Launch post: edits don't spend credits or wait for an LLM. Limits: latest runtime only, not read-only chats or mobile viewports, "Tailwind-compatible values depend on what your project defines." Jun 8 added a floating toolbar, layers viewer and measure overlay; Jun 19 added **Annotations mode** (click-to-comment feedback). ([Design mode](https://v0.app/docs/design-mode), [changelog](https://v0.app/changelog)) **Fix with v0** (auto-fix of runtime errors) is free 10/day on paid plans (Jul 31/Aug 14). Cmd+K palette, PR merge-conflict resolution, prompt-history recall.

**Publish.** **Publish** in the chat header → confirm Vercel project name → choose visibility (Public, Team, or **Team or password**, Aug 28) and domain → Commerce mode review if Stripe/Shopify present → production deploy; later **Publish Changes** keeps the URL. GitHub-backed projects: v0 "creates a working branch when the chat first has a code change", "Every code change creates an automatic commit", "v0 never pushes directly to main"; Publish "creates or reuses the chat's pull request, merges it into the base branch, and waits for the production deployment" (unified flow Sep 1). The deployment popover shows CI status. **Projects** "connect chats to your actual app, including deployments, environment variables, and domains"; env vars are pulled from Vercel automatically. Analytics/Inspect link out to Vercel's dashboards; a **Usage and Activity** dashboard opened to all users (Aug 14). The "Built with v0" badge was removed from published apps (Aug 14). ([Quickstart](https://v0.app/docs/quickstart), [FAQ](https://v0.app/docs/faqs))

**Collaboration.** **Invite** in the header with view/edit permissions; team chats visible by default (Sep 10); personal accounts converted to team workspaces (Oct 6); shared credit pool; MCP server and Platform API v2 (GA Aug 5) to drive v0 programmatically.

### 3.2 Architecture and generation technique

- **Composite model** (Jun 2025, still the described foundation): pre-processing RAG over "documentation, UI examples, your uploaded project sources, internal Vercel knowledge"; a swappable frontier base model; a speed-optimised **Quick Edit** model for small changes; and **AutoFix**, a custom streaming post-processor (`vercel-autofixer-01`, RL-fine-tuned with Fireworks) "constantly checking the output stream for errors, inconsistencies, and best practice violations", then a final pass and linter. Internal evals: v0-1.5-md 93.87% error-free vs Sonnet 4 at 64.71%; the autofixer hit 86.14% at 8,130 chars/s. ([Composite model family](https://vercel.com/blog/v0-composite-model-family))

## 4. Cross-cutting lessons for a competitor (Makeborne)

1. **Credit anxiety is the universal #1 complaint, and it is a UX problem more than a pricing problem.** Lovable shows cost only *after* a run and admits "no upfront credit estimate"; Bolt charges for every Attempt-fix click; v0 charges for failed generations. Show an estimate range before Build, a live meter during, and a receipt after — and make the receipt list evidence (files changed, checks passed), not just a number.
2. **Make deterministic edits free and say so loudly.** The three features users love without resentment are exactly the ones that bypass the LLM: v0 Design Mode ("don't spend credits or wait for an LLM"), Bolt's Select edits ("only consume tokens when saved"), Lovable's inline text edits (100 free/day). For client-ready sites/decks/books, copy, image swap, colour/type/spacing and reorder should be direct-manipulation, never prompts.
3. **Everyone converged on Plan → Build with a cheap plan tier, then had to make the plan *editable*.** Lovable added highlight-a-section → diff and plan versioning; Bolt shows an "Implement plan" button; v0 shows a task list. Ship the editable plan from day one and persist it (`plan.md`-style) so clients can approve scope before spend.
4. **Constraints before generation beat correction after.** All three "regress to the same centroid on an underspecified prompt" (violet, Inter, rounded cards). Lovable's answer was a pre-build design card with preselected defaults — then it removed the direction previews in Oct 2026, a sign that even one extra screen hurts activation. Makeborne's structural advantage: the *client brand kit* is the constraint, captured once in the CRM record and applied to website, deck and book, so no per-project design quiz is needed.
5. **Treat a design system as an adapter with a verification rule, not a style guide.** v0: "If a component, prop, or token cannot be verified from the sources, v0 should not use it." Lovable: adherence checks "flag raw colors, one-off values, inline style overrides" and retry. Build a brand-token linter into the generation loop for every format.
6. **Self-verification is expensive, slow and therefore rationed.** Lovable's browser testing is "conservative by default", "slower than normal actions" and "not reliable for subtle visual design"; v0 shows screenshots selectively. Pick cheap checks per format (link/404 scan, mobile snapshot diff, deck overflow detection, print bleed/margins) and run them *always*, reserving agentic browser tests for interactive flows.
7. **"Done" claims that aren't true destroy trust faster than slow builds.** ("It frequently claims to have implemented changes it hasn't.") End every run with evidence — before/after screenshots, a changes list, check results — so the user never has to verify by hand.
8. **Preview must be the production runtime.** Bolt's in-browser WebContainer preview is its biggest structural weakness (env vars, loose deps, auth redirects break only after publish); v0 moved to VMs in Feb 2026 precisely so "Previews now run your full application exactly as it would in production." For static-ish client sites this is easy: render the preview from the same build artifact you publish.
9. **Review links are table stakes in 2026; approval is not.** Lovable: named preview links with password/expiry, guest comments; Bolt: private sites, preview comments → prompts; v0: Team-or-password visibility, Annotations. None has a client-facing approval state (requested → changes → approved → published) or per-client review history. That gap is Makeborne's wedge; make comments feed the agent *and* the CRM timeline.
10. **Pinned preview comments that become prompts are now standard** (Lovable Jun, v0 Jun, Bolt Oct 2026). Implement them account-free for clients, with the agency deciding which to send to the agent.
11. **Snapshot publishing with an explicit "Publish changes" dot** (Lovable, Bolt "Update", v0 "Publish Changes") is the right model for client work: the live site never changes without a human click, and unpublish/restore (Lovable's 60-day restore) should exist.
12. **Security/trust gates at publish are becoming expected** — Lovable's 10-second Quick scan and Trust Center, Bolt's token-free security audit, v0's deployment protection. The agency analogue is a "client-ready check" (SEO cards, broken links, mobile view, accessibility, brand compliance, print spec) in the publish dialog that *warns* by default and can be set to *block*.
13. **Model routing: hide it by default, expose cost tiers on request.** v0 removed its model picker for auto-selection (Aug 2025) and reinstated tiers with hover pricing within a year; Bolt collapsed models into Standard/Max; Lovable pins projects to a provider to keep prompt caches warm. Offer Standard/Max-style tiers, keep per-project provider stickiness, and show the rate.
14. **Support and refunds are the second-biggest complaint for all three** ("No refunds, no help"; "support messages went unanswered"). A written policy of refunding runs that fail verification, plus a "dispute this generation" button, would be a differentiator that costs little at Makeborne's scale.
15. **Multi-format is wide open.** Bolt Slides (decks as React) and Lovable's "Generate files" (one-off PDF/PPTX in chat) prove demand, but neither produces brand-consistent, client-reviewable decks or print books, and none of the three has a CRM. Position Makeborne as "one brand, three formats, one review loop" rather than as a fourth app builder.
