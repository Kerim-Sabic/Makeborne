# Trusted publication compiler: local qualification, 2026-10-13

This package adds the worker-side compiler/render boundary. It does not activate a production executor or deploy application/Worker/database changes.

## Implemented

- `src/lib/projects/publication-compiler.ts` takes a service-claimed binding, exact validated saved ArtifactVersion and original assets already resolved under current project authority. It reuses `websiteBuildInput`, the pinned React/Vite toolchain, `validateBuildReceipt` and `compiled-output` retention. Source bytes and asset descriptors are independently checked; the database version-content hash remains a separate opaque claim binding.
- Compiler configuration requires an exact qualified runtime image ID and renderer ID. The operator adapter checks the Docker image ID before starting project execution and checks the returned build receipt again afterward. A stale local image was refused with TOOLCHAIN_MISMATCH during qualification; rebuilding the existing Dockerfile used cached layers.
- Unverified browser snapshots, compiled bundles and page messages are never accepted as publication evidence. The browser receives only retained manifest bytes and captures through a separate CDP world plus native DOM.getOuterHTML. Changing page DOM prototypes and sending a forged snapshot message did not change the captured result.
- The controller emulates the real HTTPS site origin under the actual hosting CSP. It intercepts only bounded manifest-listed GET document/script/stylesheet/font/image resources. Other requests, WebSockets, popups, downloads, missing assets, failed fonts/images and runtime errors fail the preparation. Service workers are blocked; WebRTC constructors are disabled before project code. Browser subprocesses receive a small operating-system environment without app/provider/database secrets. A dead proxy, failed DNS resolution, disabled QUIC and disabled direct WebRTC UDP add restrictions. These browser controls do not qualify an OS network sandbox for production.
- Every declared route is captured separately (maximum 20; root required), under the same retained build. Snapshots total at most 8 MB, with 3.9 MB per route. The outer worker must bound total execution. A route carries its exact rendered stylesheet list, including Vite dynamic-import CSS. Unsupported extra entry scripts and inline initializers fail before publication.
- Receipts bind preparation/actor/workspace/project/artifact/version/publication revision/content hash/slug/mode, canonical source and original asset manifest hashes, toolchain, exact runtime image, renderer implementation identity, hosting policy, build file manifest, entry scripts/styles, per-route snapshot hashes and stylesheets. Immutable compiled files are read back before the build marker; the publication receipt marker is written and read back last after rendering. Root composition binds the final sanitized output separately.
- Hosting accepts only manifest-backed safe Vite `/assets/` JS/CSS/WOFF2 files plus safe project PNG/JPEG/WebP paths. Magic headers and byte hashes are checked before retention as site files. Limits remain 6 MB total, 1.5 MB/script, 1.2 MB/stylesheet, 2 MB/image or font, 40 images, and at most 128 public files. Arbitrary JSON, HTML, SVG, nested Vite paths and filesystem reads are unsupported. The existing CSP is unchanged.
- Worker mb4 calls `makeborne_read_hosted_site_v3(p_slug,p_path)`, preserving legacy sites through the database reader while requiring exact declared routes for new trusted output. It validates file MIME against the allowed path and verifies content hashes. Legacy WebP-normalized image paths remain compatible.

## Qualification

- `node src/lib/projects/check-publication-compiler.cjs`: 6 offline groups for binding, tampered source/toolchain/revision/runtime receipts, compiled bytes, interrupted/corrupt storage, renderer failure and marker ordering.
- `node scripts/check-publication-browser.cjs`: 6 actual-browser groups for forged postMessage/native DOM capture, external network/socket denial, missing images/fonts, independent busy-loop deadline, cancellation and wrong renderer identity.
- `MAKEBORNE_VERIFY_LOCAL_PUBLICATION=true` with `node scripts/check-publication-runtime.cjs`: actual existing Docker/Vite adapter, immutable output retention and Chromium capture; two routes, original PNG, seven real WOFF2 fonts; wrong version/assets and cancellation refused. Final composed documents run at 390 and 1440 pixels with JavaScript enabled and disabled, with distinct route headings, loaded images/fonts, working interactive count button and no runtime errors/overflow.
- `node src/lib/hosting/check-hosting.cjs`: 20 hosting groups, including exact-route v3 requests and safe Vite module/font delivery.
- Full TypeScript and scoped ESLint passed during this package.

The qualified local runtime candidate is `sha256:505d5483990e8892fd3b70e11120c68f470587ba28fe445d4fab4c6974c92697`. The renderer identity is computed from the actual Chromium version plus SHA256 of the controller and delivery-policy implementation files. `localPublicationRendererId(browserVersion)` observes this identity for operator qualification; production must pin a separately approved identity rather than accepting whichever code happens to be installed.

## Remaining production boundary

`publication-adapter.mjs` and `publication-renderer.mjs` are operator-only. Never import them into request handlers. Compilation has existing container CPU/memory/PID/filesystem/network limits. Local rendering has a browser-process watchdog, restricted environment and browser network controls; it does not establish production container/VM network isolation, hard CPU/RAM quotas, provider lifecycle, crash durability or multi-tenant security. A production executor must be separately qualified and configured before dispatch is enabled. No app keys or database authority may enter project execution.

Roll out Worker mb4 only with the v3 reader migration and matching trusted publisher. Keep old live bytes on preparation failure. Rollback must keep receipt enforcement and compatible route readers; do not restore browser-output promotion. No production/staging/provider/paid calls, commits or deployment occurred in this package.
