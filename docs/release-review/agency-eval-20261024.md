## What the first run found (kept, not hidden)

The first run passed 3/8. The failures were:

1. **A real integration bug, now fixed in `src/lib/knowledge/extract.ts` (commit 85dc2a2).** XLSX currency cells keep their amount in `value`, while CSV cells use `number`. Stage 3 read only `number`, so real Excel price lists never produced price suggestions. The stage 3 harness had used a hand-built record. Extraction now reads either field, and a new regression check runs the real XLSX and CSV parsers (`check-knowledge.cjs`, 15/15).
2. **The eval's citation verifier was too strict.** It now verifies the extractor's structured lines, as described above. Nothing changed in the product.
3. **A broken-image fixture tested the wrong thing.** The fixture had an asset row whose stored object was missing. The resolver cannot tell that from a storage outage, so it reports the image as *not checked* (listed in coverage). It does not call it broken. That behaviour is correct and is now measured separately: `team.png` → not checked, and listed in coverage. A deleted asset that the version still references (`clinic.png`) → broken, and caught.
