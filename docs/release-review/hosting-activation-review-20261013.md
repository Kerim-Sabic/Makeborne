There is **no demonstrated fundamental SDK image-parameter mismatch** requiring replacement with snapshots or legacy runtimes.

## Concrete packaging gaps and qualification risks

1. **Renderer image recipe is absent.** The infrastructure tree contains controller and compiler Dockerfiles, but no renderer Dockerfile or dedicated renderer dependency lock. The compiler package manifest does not declare Playwright. Copying the render entry scripts alone cannot provide a working renderer.

   A minimal renderer package must include Node 24; a pinned Playwright package and matching Chromium binary; browser OS libraries; `publication-renderer.mjs`, render entry/watchdog, protocol and `identity.mjs`; and both customer-site policy modules. With scripts at `/opt/makeborne`, the relative policy imports resolve to `/opt/customer-sites/site-policy.js` and `website-policy.js`. Preserve those paths or make a separately reviewed packaging change. Establish ES module interpretation for `.js` policy files. Bake the browser into a path discoverable with `HOME=/tmp` (for example an explicit image-level browser path); a browser installed only in the build user's home cache is insufficient. Prove non-root launch with `chromiumSandbox:true`; removing the sandbox flag is not a qualification fix.

2. **Compiler input directory is not prepared by its Dockerfile.** `infra/project-runtime/Dockerfile` copies trusted compiler files and selects `USER node`, but never creates `/input`. The local Docker adapter supplied an input mount; the Vercel executor uses `mounts:{}` and writes `/input/request.json` before starting a command. Installed `Session.writeFiles` explicitly uses the sandbox's default user. A normal non-root user cannot create a new directory at `/`. Add the directory and correct ownership in a reviewed image recipe, or intentionally revise the input contract to a verified writable path. Provider-side directory provisioning is currently unobserved and must not be assumed. The existing recipe therefore does not establish usable input IO on Sandbox.

3. **Exact provider image string needs qualification.** The SDK documents `sandbox.image` as a digest-pinned repository reference and returns the API value unchanged. The executor compares it to the configured image with exact string equality. A provider expansion of a short repository name, removal of `vcr.vercel.com/`, or digest normalization can refuse an otherwise valid image. No actual mismatch was observed because no VM was created. Record the returned canonical reference in the first image-only probe; use that immutable form in approval data, or review explicit normalization that preserves repository and digest identity. Do not weaken the check to an arbitrary matching suffix.

4. **Image readiness and execution budgets remain unmeasured.** Creation allows ten seconds; compiler session TTL is at most 75 seconds, renderer at most 35 seconds, with lower command/work budgets and a five-minute SQL lease shared by the attempt. Rendering creates a separate VM for each requested route. A cold image or many declared routes may exceed these budgets. First qualify one route, then the supported route/asset limits. Do not request larger quotas or change timeouts based solely on local performance.

These are prerequisites to an honest activation request. None is cured by supplying a database password, storage key, or generic managed image.
